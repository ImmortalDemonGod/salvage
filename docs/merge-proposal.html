One Game From Two Docs: a merge proposal

Jam runs Jul 30 → Oct 5 (9.5 weeks) · Builds on Marc's Project Proposal and Glass_Goat's Presentation_Simplified

Both design docs already agree on the game we want to make: tactical turn-based combat where disabling the enemy matters more than damaging them, no mana bar, every action has a real cost, set in a fallen underwater civilization. This doc proposes one way to merge the two combat designs and size the whole game so we finish with time to polish. Everything here is a starting point for tonight's discussion, not a verdict.

01

What each doc contributes

Marc's proposal gives us the identity: the disable-first pillar, the relic-gated Zelda-style exploration, the story of the fallen civilization, and a clear "features we won't build" list. The scope instinct is already in the doc.

Glass_Goat's doc gives us the buildable implementation: instead of giving every enemy five breakable parts with their own durability, a skill can simply inflict the condition directly: hit the eye, enemy is Blinded; hit the fin, enemy is Slowed. Same tactical choice, a fraction of the code and art.

Proposed merge Glass_Goat's conditions carry Marc's pillar. Regular enemies use condition-inflicting skills. Bosses get the full body-part targeting treatment (multiple targetable parts, breaks that end phases) as showcase set-pieces. Every fight is still "choose what to disable"; we pay for the expensive version only where judges will actually see it.
02

Sizing the game to the jam

Two things worth designing around:

  • Jam judges typically play 15–20 minutes per entry. A 2–4 hour game spends most of its content on players who will never reach it. A 30–45 minute game puts everything we build in front of every player.
  • Last jam taught us where the time goes. We shipped one boss fight and were still tuning mechanics on deadline night. The lesson isn't "aim lower." It's that testing and tuning, not writing features, is where jam time disappears. So this plan budgets for tuning from day one.

That second point is also the main question to weigh on the combat system. The two docs trade different costs:

Full limb system (all enemies)Full exhaustion system
Build costHigh: part rigs, break effects, art per part, per enemyLow: mostly standard turn-based code
Tuning costLow: each fight resets, so each fight can be tuned aloneHigh: resources carry across fights, so tuning changes need full-run replays

The exhaustion system's tuning cost comes from specific pieces: two death conditions that interact (HP and stamina both lethal, failed dodges drain both), three threshold versions of every skill, and HP that barely heals, which makes a mistake in fight 2 change the difficulty of fight 8. Each of these multiplies the full-run playtesting we'd need inside the jam window. So this plan keeps the simplest core (actions cost stamina, stamina regenerates, HP is the sacred resource) and moves the rest to the post-jam list rather than cutting it forever.

Post-jam parking lot

Not deleted, just parked. If the game is worth continuing after Oct 5, this is the roadmap:

  • Post-jamInventory + equipment: needs a longer game to pay off.
  • Post-jamParty members: a full system of its own; the jam game is a solo character.
  • Post-jamResonance (the spendable resource from Marc's doc, earned by breaking parts): for the jam, successful disables refund stamina instead, which keeps the same "tactical play is rewarded" incentive with zero new systems.
  • Post-jamStamina-death, threshold skill tiers, desperation moves, hard-to-heal HP: the full exhaustion vision, once there's time to tune it properly.
  • Post-jamSave/load: jam build autosaves at dungeon entrances.
04

How we avoid last jam's deadline crunch

  • Vertical slice by end of week 2 (~Aug 13): one fight, one puzzle, one relic gate, playable start to finish. If the slice slips, the content budget shrinks to match, agreed in advance, so it's automatic instead of a hard conversation later.
  • Automated balance testing from day 1. If we keep combat deterministic (or seed its randomness), we can simulate thousands of bot fights per balance change, catching unwinnable fights, degenerate strategies, and fight-length problems before any human sits down. Simulation answers "is it winnable"; our weekly playtest answers "is it fun." ImmortalDemon builds this in week 1.
  • One scheduled playtest evening per week, so feel-testing happens all jam long instead of the final weekend.
  • Content freeze Sep 26: the last 9 days are polish and playtesting only. Polish is where jam ratings are won, and it only exists if we protect it on the calendar.
